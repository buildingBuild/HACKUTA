# RGB Sync (clip-synced keyboard) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/rgb` plays a FaZe vs [team] CS2 highlight clip. At each cued moment the on-screen virtual keyboard and Yao's ASUS laptop keyboard (through a local companion) fire matching lighting effects. After each effect the lights go off.

**Architecture:**
- A standalone Node companion (`companion/`, outside the npm workspaces) drives the ASUS Aura HID interface. It exposes `127.0.0.1:7777`.
- The web page runs the YouTube IFrame player, detects cue crossings from the playhead, animates a CSS virtual keyboard, and POSTs each effect to the companion. The companion is optional.
- No server or DB changes.

**Tech Stack:** Node 20+ ESM + TypeScript run by `tsx`, `node-hid@3` (companion only), `node:http`, `node:test`; React 19 + Vite (web), YouTube IFrame API.

**Spec:** `docs/superpowers/specs/2026-11-15-rgb-sync-design.md`

## Global Constraints

- **`node-hid` lives only in `companion/package.json`.** The root `workspaces` stays `["web","server"]`, and Railway never installs it.
- **Aura device:**
  - Match on VID `0x0B05`, PID `0x19B6`, usagePage `0xFF31`, usage `0x79`.
  - Every command is a 64-byte feature report, zero-padded:

    | Command | Bytes |
    |---|---|
    | init | `5D` + ASCII `ASUS Tech.Inc.` |
    | brightness | `5D BA C5 C4 <0..3>` |
    | mode | `5D B3 00 <mode> R G B <speed> <dir> 00` |
    | set | `5D B5` |
    | apply | `5D B4` |

  - Speeds: slow `E1`, med `EB`, fast `F5`.
  - Modes: 0 static, 1 breathing, 2 colour cycle, 10 strobe (unverified).
- **Every effect ends with the lights off** (brightness 0). The companion also turns them off on SIGINT/SIGTERM/exit.
- Host-driven flashes no faster than about 4 Hz (≥ 120 ms per step). Use hardware modes for smooth animation.
- **Effect names** = `LiveEventType` from `shared/types.ts`: `round_win`, `round_loss`, `ace`, `clutch`, `match_win`, `match_start`. The others are ignored.
- **Scope:** the keyboard reacts only to the clip on `/rgb`. Never subscribe to `/api/live` or the director console.
- **Companion HTTP:**
  - Bind to `127.0.0.1` only.
  - Every response carries `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Private-Network: true` and `Access-Control-Allow-Headers: content-type`. `OPTIONS` returns 204.
- **Copy:** never claim endorsement by FaZe, ASUS or Valve.

## Review Focus

1. **Companion not running:** the page plays the clip with virtual effects, shows "Keyboard not connected", and logs no uncaught errors. Requests time out after ≤ 400 ms. *(Task 3 test: `sendEffect` resolves `false` when fetch rejects or times out.)*
2. **Seeking or scrubbing:** a jump of more than 1.5 s fires no cues, so seeking past five moments doesn't fire all five. Seeking backward re-arms the earlier cues. *(Task 3 tests in `cues.test.ts`.)*
3. **Back-to-back cues** less than an effect apart: the new effect cancels the old one, and the lights still end off. *(Task 1 test.)*
4. **Keyboard missing or HID error mid-effect:** the server stays up, `/status` reports `device: false`, and `POST /effect` returns 200 `{played:false}`. *(Task 2 test with a throwing driver.)*
5. **Ctrl+C mid-effect:** the lights turn off before exit. *(Task 2: covered by `shutdown()` calling `off()`, unit-tested.)*

### Task 1: Companion driver + effects engine

**Files:**
- Create: `companion/package.json`
  - `"type":"module"`, private.
  - deps `node-hid@^3`; devDeps `tsx`, `typescript`, `@types/node`.
  - scripts:

    - `test`: `tsx --test src/*.test.ts`
    - `test-fx`: `tsx src/cli.ts`
- Create: `companion/tsconfig.json` (strict, ES2022, NodeNext)
- Create: `companion/src/aura.ts`
- Create: `companion/src/effects.ts`
- Test: `companion/src/effects.test.ts`

**Interfaces:**
- Produces, `aura.ts`:
  - `interface Lights { off(): void; color(r: number, g: number, b: number): void; mode(m: AuraMode, r: number, g: number, b: number, speed?: Speed): void }`
  - `type AuraMode = 0 | 1 | 2 | 10`
  - `type Speed = 'slow' | 'med' | 'fast'`
  - `openAura(): Lights | null`: returns `null` when no device. It sends init plus brightness 3 on open.
  - `off()` sends brightness 0. `color`/`mode` send brightness 3 first, then mode + apply. Skip set (`B5`) except on open.
- Produces, `effects.ts`:
  - `type EffectName = 'round_win' | 'round_loss' | 'ace' | 'clutch' | 'match_win' | 'match_start'`
  - `const EFFECTS: Record<EffectName, Step[]>`, with `type Step = { do: (l: Lights) => void; ms: number }`
  - `class Player { constructor(lights: Lights, sleep?: (ms: number) => Promise<void>); play(name: string): Promise<boolean>; stop(): void }`
  - `play` returns `false` for an unknown name. It cancels any running effect. After the last step it calls `off()`, unless it was superseded.
- Timings:

  | Effect | Steps |
  |---|---|
  | `round_win` | breathing red, slow, 2000 ms |
  | `round_loss` | static `(60,0,0)`, 1000 ms |
  | `ace` / `clutch` | 8 × (white 125 ms, red 125 ms) |
  | `match_win` | colour cycle, fast, 4000 ms |
  | `match_start` | white 400 ms, red 600 ms |

- [ ] **Step 1: Write failing tests** in `effects.test.ts` with a `FakeLights` that records calls and an instant `sleep`:
  - `play('round_win')` → the first call is `mode(1,255,0,0,'slow')` and the last call is `off`.
  - `play('nope')` resolves `false` with no calls.
  - Start `play('ace')` and, without awaiting, call `play('round_win')`. Both settle, `off` comes last, and no `ace` step is recorded after the first `round_win` call.
  - Every key in `EFFECTS` ends in `off` when played.
- [ ] **Step 2:** `cd companion && npm install && npm test`. Expected: FAIL (module not found).
- [ ] **Step 3:** Implement `aura.ts` and `effects.ts`. Cancellation uses a generation counter checked after each `await sleep`.
- [ ] **Step 4:** `npm test`. Expected: all pass.
- [ ] **Step 5:** `git add companion && git commit -m "feat(rgb): companion Aura driver + effects"` (make sure `companion/node_modules` is gitignored; the root `node_modules/` pattern already covers it).

### Task 2: Companion HTTP server + CLI

**Files:**
- Create: `companion/src/server.ts`
- Create: `companion/src/index.ts`
- Create: `companion/src/cli.ts`
- Test: `companion/src/server.test.ts`

**Interfaces:**
- Consumes: `openAura`, `Lights`, `Player` (Task 1).
- Produces:
  - `createServer(opts: { lights: Lights | null }): { server: http.Server; shutdown(): void }`
  - Routes:
    - `GET /status` → `{ ok: true, device: boolean }`
    - `POST /effect` with body `{ type: string }` → `{ played: boolean }`, always 200 (400 on bad JSON)
    - `OPTIONS *` → 204
    - anything else → 404 `{error}`
  - `shutdown()` stops the player and calls `lights?.off()`, swallowing errors.
  - Driver errors during play are caught: the response is `{played:false}`, and `device` flips to `false`.
  - `index.ts` calls `openAura()`, listens on `127.0.0.1:7777`, logs `RGB companion on http://127.0.0.1:7777 (keyboard: found|not found)`, and wires SIGINT/SIGTERM to `shutdown()` then `process.exit(0)`.
  - `cli.ts <effect>` opens Aura, plays one effect, and exits.

  - `POST /effect {type:'round_win'}` with `FakeLights` → `{played:true}`.
  - The same with a throwing `Lights` → 200 `{played:false}`, and the next `/status` shows `device:false`.
  - `shutdown()` with `FakeLights` records `off`.

**Interfaces:**
- Produces:
  - `type Cue = { t: number; type: EffectName }`. `EffectName` is defined locally in `cues.ts` as `Extract<LiveEventType, 'round_win'|'round_loss'|'ace'|'clutch'|'match_win'|'match_start'>`, imported type-only from `../../../../shared/types`.
  - `crossed(prev: number, now: number, cues: Cue[]): Cue[]`:
    - Returns the cues with `prev < t <= now`, but only when `0 <= now - prev <= 1.5`.
    - Otherwise (a seek or a backward jump) returns `[]`.
  - `clip.ts`: `export const CLIP: { videoId: string; title: string; opponent: string; event: string; cues: Cue[] }`
  - `companion.ts`:
    - `const COMPANION = 'http://127.0.0.1:7777'`
    - `companionStatus(): Promise<boolean>`
    - `sendEffect(type: EffectName): Promise<boolean>`
    - Both use `AbortSignal.timeout(400)` and never throw.

  - The bullets drop "OpenRGB, Razer Chroma, Philips Hue and Govee" in favour of "Watch a FaZe clip and your keyboard lights up with every round" and "No RGB gear? The virtual setup plays along".

**Interfaces:**
- Consumes: `CLIP`, `crossed`, `sendEffect`, `companionStatus` (Task 3).
- Produces:
  - `youtube.ts`: `loadYouTube(): Promise<typeof YT>`. It loads `https://www.youtube.com/iframe_api` once, with minimal local typings and no dependency.
  - `VirtualKeyboard`: `<VirtualKeyboard effect={{ name: EffectName, key: number } | null} />`.
    - 4 keyboard zones plus a light bar, dark when idle.
    - The effect plays through CSS class `vk--<name>`, using animation durations that match the companion timings.
    - It returns to dark on `animationend`. `key` restarts the animation.
- Page behaviour:
  - **Layout:** player (16:9) on the left; virtual keyboard plus companion status pill on the right; cue list below. Stack on mobile, with a 16 px gutter.
  - **Playback loop:** a `requestAnimationFrame` loop reads `player.getCurrentTime()` while playing. For each `crossed()` cue it sets the effect and calls `sendEffect`.
  - **Companion status:** polled every 3 s.
    - Green "Keyboard connected"
    - Grey "Keyboard not connected: showing virtual setup" (with a hint: `cd companion && npm start`)
  - **Cue list:** clicking a cue seeks to `t - 3`.
  - **Marking mode:** a toggle button.
    - While it's on, keys `w`/`a`/`l`/`m`/`c`/`s` (`round_win`/`ace`/`round_loss`/`match_win`/`clutch`/`match_start`) push `{t: rounded to 0.1, type}`.
    - A "Copy cues" button copies `JSON.stringify(cues)`.
    - Marked cues replace the in-memory list for this session.
